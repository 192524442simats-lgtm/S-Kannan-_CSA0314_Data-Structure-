Traditional Approach

Manual Price Comparison

Shoppers manually collect paper circulars, browse disconnected supermarket apps, or perform repetitive store visits to find discounts.

  • High Cognitive Fatigue: Comparing \(m\) items across \(v\) stores requires \(O(m \times v)\) manual searches.
  • Error Prone: Consumers frequently miss rollbacks, digital coupons, or unadvertised specials.
  • Suboptimal Basket: Shoppers buy all groceries at a single store, spending 20%–35% more on average.

Proposed System

Smart Min-Heap Priority System

Aggregates multi-vendor price points into a binary Min-Heap data structure to guarantee mathematical cost optimality.

  • Instant Root Retrieval \(O(1)\): The cheapest vendor is always preserved at the root node of the Min-Heap.
  • Efficient Updates \(O(\log n)\): Rapid insertion and heapify-up/down operations allow real-time price synchronization.
  • Optimal Basket Splitting: Aggregates global minimums to project hundreds of dollars in annual grocery savings.
  • Algorithmic Transparency: Visual binary tree display with complete execution traces for academic demonstration.

Enhancing Grocery Cost Savings Using a Smart Grocery Price Comparison System Compared with Traditional Manual Price Comparison

A comprehensive study and implementation of binary Min-Heap Priority Queues to eliminate human cognitive bias, mitigate search latency, and optimize household grocery expenditure across distributed retail vendors.

Problem Statement

Traditional grocery price comparison is intrinsically manual, fragmented, and inefficient. Consumers must cross-reference physical promotional flyers, navigate multiple retailer applications, or physically visit competing supermarkets.

This manual methodology leads to severe cognitive overload, high latency, missed short-term flash discounts, and purchasing decisions constrained to a single supermarket—resulting in consumers overpaying by an estimated 20% to 35% on identical staples.

Project Objectives
  • Algorithmic Price Ingestion: Structure vendor pricing into uniform objects with names, units, categories, and stock availability.
  • Min-Heap Priority Queue: Ensure the absolute lowest price is maintained at the root node for \(O(1)\) lookup.
  • Ascending Ranking: Enable \(O(n \log n)\) ascending vendor sorting via successive \(O(\log n)\) extract-min operations.
  • Savings Optimization: Quantify cost savings against worst and average vendor benchmarks with projected annual gains.

Module Technical Specifications & Complexity Analysis

Theoretical time and space bounds as presented in our project defense.

Module 1: Product Data Management
Time: O(n) Processing Space: O(n) Storage

Responsible for managing the collection of multi-vendor grocery items. Linear searching and filtering through the catalog requires examining each of the \(n\) records in the worst case, yielding \(O(n)\) time complexity. Adding a record is \(O(1)\) amortized, while full deletions or updates require a single scan of the array.

Space Complexity: \(O(n)\) where \(n\) is the total number of products stored in memory and persisted in HTML5 LocalStorage.
Module 2: Price Comparison & Min-Heap Ranking
Time: O(log n) Per Insertion/Extraction • O(n log n) Total Space: O(n) Heap Array

The core algorithmic engine. When comparing vendors for a specific grocery item, offerings are inserted into a Complete Binary Tree structured as a Min-Heap.

  • • Insertion: Placing a new vendor price at array index \(k\) and executing heapifyUp() traverses along the tree height \(h = \lfloor \log_2 n \rfloor\), executing at most \(\log n\) parent swaps: \(O(\log n)\).
  • • Peek Root: Reading index 0 yields the cheapest vendor immediately: \(O(1)\).
  • • Extraction (Extract-Min): Removing the root and restoring the heap property with heapifyDown() takes \(O(\log n)\) time.
  • • Full Ascending Ranking: Performing \(n\) successive extractions to sort all vendors in ascending price order requires \(O(n \log n)\) time complexity (Heap Sort).
Index Mapping: Parent: \(\lfloor(i-1)/2\rfloor\), Left Child: \(2i+1\), Right Child: \(2i+2\). Stored compactly in contiguous memory with \(O(n)\) auxiliary space.
Module 3: Recommendation & Cost Savings Optimizer
Time: O(log n) Extraction Space: O(n)

The recommendation engine inspects the root of each item's Min-Heap to determine the cheapest retailer, computes the delta against the maximum/worst vendor (\(P_{\text{worst}} - P_{\text{root}}\)), and evaluates aggregate multi-vendor cart savings.

Formula: \(\text{Savings} = \sum_{k=1}^{K} \left( \max(P_{k}) - \min(P_{k}) \right)\). For \(K\) basket items, extracting the optimal prices takes \(O(K \log n)\) time. Space complexity remains \(O(n)\).
